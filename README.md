# SIMS — SMM Insurance Management System

ASP.NET Core 8 / React / PostgreSQL insurance management platform.

## Stack

- **Backend:** ASP.NET Core 8, Entity Framework Core 8, PostgreSQL (Azure), Azure Blob Storage
- **Frontend:** React + TypeScript + Vite (port 5173)
- **API:** port 5000
- **Auth:** Microsoft/Azure AD (MSAL)

## Quick start

```bash
# Backend
cd backend
ASPNETCORE_ENVIRONMENT=Development dotnet run --project src/SIMS.API

# Frontend
cd frontend
npm run dev
```

## Common commands

```bash
# Build
cd backend && dotnet build

# Add a migration
~/.dotnet/tools/dotnet-ef migrations add <Name> \
  --project src/SIMS.Infrastructure \
  --startup-project src/SIMS.API

# Apply migrations
ASPNETCORE_ENVIRONMENT=Development \
  ~/.dotnet/tools/dotnet-ef database update \
  --project src/SIMS.Infrastructure \
  --startup-project src/SIMS.API

# Frontend type check
cd frontend && npx tsc --noEmit
```

## EF Core + Rating tables — important gotcha

All rating-related tables (`rating_plans`, `rating_plan_versions`, `factor_tables`, `factor_rows`, `eligibility_rules`, `carrier_rating_assignments`, `equipment_types`, `territories`, `quote_rating_snapshots`, `quote_rating_lines`, `rating_plan_version_impact_previews`) were created via raw SQL migrations with lowercase snake_case column names.

Because there is no global `UseSnakeCaseNamingConvention()`, EF Core defaults to quoting PascalCase identifiers (`r."Id"`, `r."RatingPlanId"`). PostgreSQL rejects these against lowercase columns with:

```
42703: column r.Id does not exist
```

**Fix:** Every rating entity configuration must include explicit `HasColumnName("snake_case_name")` for all properties, including base entity columns (`id`, `created_at`, `updated_at`, `is_deleted`, `deleted_at`).

**Exception:** Columns added later via `migrationBuilder.AddColumn<Guid>(name: "PascalCase", ...)` — e.g. `CreatedById`, `LastEditedById` on `rating_plan_versions` — are PascalCase in the DB and do **not** need remapping.

## Manually-created migrations need designer files

Migrations created by hand (not via `dotnet-ef migrations add`) will be silently ignored unless they have a `.Designer.cs` file. Without it, the migration lacks the `[DbContext]` and `[Migration]` attributes EF needs for discovery — `migrations list` won't show them and `database update` will say "already up to date."

Minimal designer file pattern:

```csharp
// <auto-generated />
using Microsoft.EntityFrameworkCore;
using Microsoft.EntityFrameworkCore.Infrastructure;
using Microsoft.EntityFrameworkCore.Migrations;
using SIMS.Infrastructure.Data;

#nullable disable

namespace SIMS.Infrastructure.Migrations
{
    [DbContext(typeof(ApplicationDbContext))]
    [Migration("20260503230000_Rating_IM_Seed")]
    partial class Rating_IM_Seed
    {
    }
}
```

## Foreign keys into `users` table

The Identity table is named `users` (lowercase) and its PK column is `"Id"` (PascalCase, EF-managed). When writing raw SQL migrations that reference it:

```sql
FOREIGN KEY (some_col) REFERENCES users ("Id")
-- In a C# verbatim string:
REFERENCES users (""Id"")
```
