# Lane U — Core Underwriting Flow findings

**U1 [P0] — Quote status lifecycle is unreachable: no UI can mark a quote Submitted/Quoted/Declined/Expired, and `quotesApi.update` has zero callers** — `frontend/src/api/quotes.api.ts:18`, `frontend/src/pages/quotes/QuoteDetailPage.tsx:34-40` (StageBar stages "Pending Information"/"Quoted"), `SubmissionDetailPage.tsx:1263-1271` — Quotes are created as Draft and the only lifecycle actions in the UI are Bind or Delete; there is no way to record a carrier declination, mark a quote as quoted/expired, or edit any quote field (premium, dates, limits) after creation, yet the stage bar, `QUOTE_STATUS_LABELS`, and submission metrics ("X declined · Y pending", `SubmissionDetailPage.tsx:1556-1563`) all assume these transitions happen. Underwriters will delete quotes to "decline" them, destroying the declination record. — Fix: add status-change + edit actions on QuoteDetailPage wired to `quotesApi.update` (M).

**U2 [P0] — Endorsements can be created but never issued (known class, confirmed)** — `frontend/src/api/policies.api.ts:27-28` (`issueEndorsement`, zero callers), `frontend/src/pages/policies/PolicyDetailPage.tsx:149-158` — "Endorse" opens a modal that calls `addEndorsement`, creating a pending transaction; `TransactionRows` offers Complete only for Cancellation/NonRenewal/Rewrite, so endorsement transactions are permanently stuck and never change the policy premium. — Fix: add an "Issue" action on Endorsement rows in TransactionRows calling `policiesApi.issueEndorsement` (M).

**U3 [P0] — Start Renewal has no UI caller despite renewal being a first-class concept everywhere** — `frontend/src/api/policies.api.ts:42-43` (`createRenewalQuote`, zero callers), `frontend/src/pages/policies/PoliciesPage.tsx:23-30,117-118,188-194` ("Expiring ≤ 30 days / No renewal started" metric, RENEWAL_LABELS), `usePermissions.ts:26` (`canRenewPolicies` unused) — The Policies list highlights expiring policies with no renewal started and PolicyDetail has a "Renewal" stage, but there is no button anywhere to start one; the only path is manually re-keying a new submission. — Fix: add "Start renewal" button on PolicyDetailPage (Active, expiring) calling `createRenewalQuote` and navigating to the created quote/submission (M).

**U4 [P0] — Rating panel hard-blocks Calculate for GL/AL/APD quotes because it gates on IM equipment** — `frontend/src/components/quotes/QuoteRatingPanel.tsx:49-52,174-175,301` — The panel always fetches `submissionIMApi.getEquipment` and disables Calculate with `equipment.length === 0`, showing "No equipment scheduled. Add equipment items to the submission before rating." even for a GeneralLiability quote whose exposures are GL classifications. Since bind requires a rated premium (`QuoteDetailPage.tsx:1237-1250`), non-IM quotes without a manually keyed premium cannot be rated or bound through the UI. Calculation-detail columns (Stated Value/Age Band/Ded Factor) are also IM-only. — Fix: gate the equipment card/blockers on `lineOfBusiness === 'InlandMarine'` and render LOB-appropriate exposure summaries (M).

**U5 [P1] — "Duplicate quote" menu item has no onClick — leads nowhere** — `frontend/src/pages/quotes/QuoteDetailPage.tsx:1357-1359` — `<MenuItem><Copy .../> Duplicate quote</MenuItem>` is rendered with no handler; clicking silently does nothing, and there is no other way to clone a quote for a second carrier option. — Fix: implement duplicate via `quotesApi.create` from current quote or remove the item (S).

**U6 [P1] — Writeup approval has no permission gate, no decline, and no way to reopen a submitted writeup** — `frontend/src/pages/quotes/QuoteWriteupPage.tsx:781-793,205-211` — When status is Submitted the only action is "Approve" (any user, including the submitter, can self-approve; `usePermissions` is never imported); there is no Decline/Return-to-Draft even though `StatusBadge` supports Declined. The inline card on QuoteDetail (`QuoteDetailPage.tsx:1612-1615`) tells users to "Reopen the full writeup workflow to change status" — which doesn't exist. — Fix: gate Approve behind `canManageUnderwriting`, add Decline/Reopen actions (M).

**U7 [P1] — Inline writeup edits on QuoteDetail are silently lost on navigation** — `frontend/src/pages/quotes/QuoteDetailPage.tsx:1075-1083,1597-1601` — Writeup payload/conditions live in local state with a manual "Save draft" button; no dirty indicator or navigation guard exists, and the adjacent "Open full writeup" link discards everything typed. GL coverage/supplemental forms on SubmissionDetail have a dirty flag but likewise no unload guard. — Fix: add a dirty indicator + confirm-on-navigate (or autosave) for the inline writeup (M).

**U8 [P1] — Insured "in-force premium" and "Policies in force" include Cancelled/NonRenewed policies** — `frontend/src/pages/insureds/InsuredDetailPage.tsx:216-218` — `activePolicies = policies.filter((p) => daysUntil(p.expirationDate) >= 0)` ignores `status`, so a policy cancelled mid-term still counts toward in-force premium, the active-policy count, and the "Policies in force" table, materially misleading account review. — Fix: filter on `p.status === 'Active'` in addition to expiration (S).

**U9 [P1] — Date-only strings parsed as UTC render one day early across core lists** — `frontend/src/pages/submissions/SubmissionsPage.tsx:60-64,66-73`, `PoliciesPage.tsx:32-38`, `InsuredDetailPage.tsx:44-48` — `new Date('YYYY-MM-DD')` yields UTC midnight, so `toLocaleDateString` in US timezones shows the previous day for effective/expiration dates and shifts "days to effective" math. `InsuredsPage.tsx:29` already appends `'T00:00:00'` to avoid exactly this — the fix exists but is applied inconsistently. — Fix: shared date-only parse/format helper used everywhere (S/M).

**U10 [P1] — Silent failures: many delete/save mutations have no onError handler** — `frontend/src/pages/submissions/SubmissionDetailPage.tsx:686-689,703-706,720-726,740-743,757-760,792-800,834-837` (delete driver/vehicle/location/prior-carrier/additional-interest/equipment/GL-class), `SubmissionLossHistoryPage.tsx:101-107,120-126` — If the API rejects (permissions, 409, trigger P0001→500), nothing is shown; the row simply stays and the user assumes the click didn't register or, worse, that it deleted. — Fix: add onError toasts (via `getSaveErrorMessage`) to all mutations (S).

**U11 [P1] — Quote delete button rendered without permission gating and offered for Quoted quotes** — `frontend/src/pages/submissions/SubmissionDetailPage.tsx:1263-1271` — The trash icon shows for every non-Bound quote for every user (Add Quote is gated on `canCreatePolicies`, delete is not), guarded only by `confirm()`. Combined with U1 it's the de-facto "decline" path, permanently destroying quote history. — Fix: gate behind permission, restrict to Draft, and prefer a status change over hard delete (S).

**U12 [P1] — Lists silently cap at 500 records with client-side filtering/metrics** — `frontend/src/pages/submissions/SubmissionsPage.tsx:92-95`, `PoliciesPage.tsx:69-72`, `InsuredsPage.tsx:37-40` — All three pages fetch `pageSize: 500` once and paginate/sort/search in memory; record 501+ is invisible with no indicator, and headline metrics (bind ratio, expiring counts, open pipeline) are computed off the truncated set. — Fix: use server paging/search or at least show a "showing first 500" warning when `data.totalCount > items.length` (M).

**U13 [P1] — AutoLiability is offered as an active LOB for submissions/quotes but is deliberately non-bindable downstream** — `frontend/src/types/quote.types.ts:35-37` (`ACTIVE_LOBS` includes AutoLiability) vs `pages/agents/AgentDetailPage.tsx:28-36` (commission LOB options intentionally omit AL as "deprecated/non-bindable, WS5-R A1.1") — Users can create AL submissions and quotes end-to-end, then hit fail-closed commission/bind blocks with no upfront warning. — Fix: either drop AL from `ACTIVE_LOBS` or show a "not currently bindable" notice on AL quote creation (S).

**U14 [P1] — InsuredDetail presents hardcoded placeholders as data** — `frontend/src/pages/insureds/InsuredDetailPage.tsx:357-360` ("3-yr loss ratio — No loss run data" always), `:528-531` ("Loss history (5 yrs): No loss run data on file" always), `:428-430` (Mailing address always "Same as above"), `:158` (Submissions "Lines" column always "—") — Loss-run data exists in the system (Loss Run CSV button works on the same page), so underwriters see contradictory "no data" claims; the mailing-address claim may simply be false. — Fix: wire real data or remove the placeholder fields (M).

**U15 [P2] — Dead toolbar buttons on SubmissionsPage: Import, Export, Filters, Effective, row kebab** — `frontend/src/pages/submissions/SubmissionsPage.tsx:182-183,241-245,322-324` — Five visible controls have no onClick (the row kebab even stops propagation, so clicking it does literally nothing while blocking row navigation). — Fix: implement or remove (S).

**U16 [P2] — Dead action buttons on InsuredDetail: COI download, Export, address Copy/ExternalLink** — `frontend/src/pages/insureds/InsuredDetailPage.tsx:416-417,511-513,574-576` — "COI", "Export", and the two address icon buttons render with no handlers; COI issuance is a core MGA servicing task users will hunt for here. — Fix: remove until implemented, or wire COI to document generation (S/M).

**U17 [P2] — Submission "Edit submission" and all exposure/prior-carrier/AI editing is not permission-gated** — `frontend/src/pages/submissions/SubmissionDetailPage.tsx:1387-1389,1827,1881,1951,2350` — Quote creation and doc generation check `canCreatePolicies`, but Edit submission, status changes, LOB edits, and every exposure add/edit/delete render for all users; read-only roles get server 403s surfaced as generic "Failed to save..." toasts (or nothing, per U10). — Fix: gate mutating controls behind an appropriate permission (S).

**U18 [P2] — Submission status can be manually set to Bound/Quoted via the editor, decoupled from quotes/policies** — `frontend/src/pages/submissions/SubmissionDetailPage.tsx:1416-1420` — The Edit-submission status dropdown offers every status including Bound; a user can mark a submission Bound with zero quotes, breaking pipeline metrics and the Policies renewal linkage that key off status. — Fix: restrict manual choices to Declined/Withdrawn/InProgress; derive Quoted/Bound from quote events (S).

**U19 [P2] — New Quote form: Program is required by validation but not marked required, and the requirement message is wrong** — `frontend/src/pages/submissions/SubmissionDetailPage.tsx:842-845,1288` — `handleCreateQuote` rejects when `!quoteForm.programId`, but the label reads "Program" (no asterisk) while Carrier/LOB/dates carry `*`; the toast lists "Program, carrier, line of business, and dates" only after submit. Users select carrier first, then wonder why LOB is empty (program change also silently clears carrier+LOB). — Fix: mark Program required and order fields Program → Carrier → LOB (S).

**U20 [P2] — Bind modal accepts incoherent dates** — `frontend/src/pages/quotes/QuoteDetailPage.tsx:616-693` — The only validation is non-empty; expiration before effective, or a bound date months in the future, submits straight to bind. Given bind creates the policy and invoice, bad dates are expensive to unwind (void-test-bind is admin-only and test-insured-only). — Fix: client-side date ordering validation + confirm summary in the modal (S).

**U21 [P2] — Quote documents card ignores attachment permissions** — `frontend/src/pages/quotes/QuoteDetailPage.tsx:815-948` (DocumentsCard) and `frontend/src/pages/insureds/InsuredDetailPage.tsx:623` with `DocumentsSection.tsx:488-489` defaulting `canUpload/canDelete = true` — SubmissionDetail and PolicyDetail pass `canUploadAttachments/canDeleteAttachments`, but the quote page and insured page render Upload/Generate/Delete for everyone; unauthorized users get raw "Upload failed" errors. — Fix: pass the same permission flags in both places (S).

**U22 [P2] — Commission split recomputes carrier/SMM amounts client-side and ignores override amounts returned by the API** — `frontend/src/pages/quotes/QuoteDetailPage.tsx:1255-1258` — `carrierCommAmt`/`smmRetentionAmt` are `ratedTotalPremium × rate` even when `quote.commissionOverride` carries authoritative `carrierCommissionAmount`/`smmRetentionAmount`; after a give-back (which reduces total premium) the displayed carrier/SMM dollars diverge from the booked values, contradicting the panel's own claim that "Carrier net and SMM commission stay unchanged." — Fix: prefer server-provided amounts when an override exists (S).

**U23 [P2] — Submission Cancel button navigates to Insureds even when the user came from Submissions** — `frontend/src/pages/submissions/SubmissionCreatePage.tsx:263-269` — Without an `insuredId` param, Cancel goes to `/insureds`, dropping the user out of the submissions workflow they started from ("New submission" on SubmissionsPage). Typed form data is also discarded without warning. — Fix: `navigate(-1)` or route back to `/submissions` (S).

**U24 [P3] — Tab label "Draft" maps to status pill "New" on the same rows** — `frontend/src/pages/submissions/SubmissionsPage.tsx:75-82,297-300` — The second tab is labelled "Draft" but filters `status === 'New'`, whose pill renders "New"; users see a "Draft" tab full of "New" chips. — Fix: align terminology (one word everywhere) (S).

**U25 [P3] — "Bind ratio (90d)" is computed over all time, and the stage bar advertises an unreachable "Released" stage** — `frontend/src/pages/submissions/SubmissionsPage.tsx:142-148,203-205` (no date filtering despite the "(90d)" label); `SubmissionDetailPage.tsx:82-90` (STAGES contains 'Released' but no status maps to idx 2, so the pipeline always skips it) — Both are small but misleading on the primary pipeline surfaces. — Fix: filter to 90 days or drop the suffix; remove 'Released' or map a status to it (S).

**U26 [P3] — Paginators only render page buttons 1–5 with no ellipsis/jump** — `frontend/src/pages/submissions/SubmissionsPage.tsx:342-353`, `PoliciesPage.tsx:303-308` — With >125 rows, pages 6+ are reachable only by repeatedly clicking "›", and the active-page highlight disappears past page 5. — Fix: windowed page numbers around the current page (S).

**U27 [P3] — Proposal/actions dropdown menus never close on selection or outside click** — `frontend/src/pages/quotes/QuoteDetailPage.tsx:283-313` (MenuButton/MenuItem) — Choosing "Preview"/"Send proposal" leaves the menu open over the page; there is no outside-click or Escape handling. — Fix: close on item click + outside-click listener (S).

**U28 [P3] — Loss-history claims can only be added or deleted, never edited** — `frontend/src/pages/submissions/SubmissionLossHistoryPage.tsx:263-306` — Fixing a typo in paid/reserved requires delete + re-key of the whole claim (and the delete has no error handler per U10). — Fix: add edit mode reusing the claim form (S).
