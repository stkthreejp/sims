# Lane X — Cross-cutting Pattern findings

**X1 [P0] — UTC "today" defaults write tomorrow's date into money/policy fields after ~7–8pm ET** — `frontend/src/pages/policies/PolicyDetailPage.tsx:213` (`policiesApi.issue(id!, { issuedDate: new Date().toISOString().slice(0, 10) })` — sent to the API directly, no user review), `QuoteDetailPage.tsx:622` (default `boundDate`) — `new Date().toISOString().slice(0,10)` = today **in UTC**. 23 occurrences across 14 files (PolicyDetailPage x4 incl. cancellation/rewrite `completedDate` 1068/1079/1194, DisbursementsPage:58 `paymentDate`, ReceiptsPage:26 `receivedDate`, InvoicesPage:15 `effectiveDate`, CarrierDetailPage:243/313, IntermediariesAdminPage:74, FeesAdminPage:168 `disableVersion` date, ProgramConfigurationAdminPage:32, SurplusLinesAdminPage:19, AdminRatingPlanDetailPage:40, AgentDetailPage:1086, ReportsPage x4). Any evening bind/issue/receipt gets stamped with the next day — silent data corruption in accounting and policy records. Sweep rule: grep `toISOString().slice(0, 10)` and `toISOString().split('T')`. — Fix: add `todayLocal()` to lib/utils and replace all 23 sites (S).

**X2 [P0] — Date-only values render one day early (UTC-midnight parse); half the app has the fix, half doesn't** — `frontend/src/lib/utils.ts:12-15` (`formatDate` does `new Date('2026-07-01')` → June 30 in US timezones), `PoliciesPage.tsx:40`, `SubmissionsPage.tsx:60`, `PolicyDetailPage.tsx:519-568` (effective/expiration/bound/issued/cancelled all wrong) — backend serializes `DateOnly` as `yyyy-MM-dd`. 47 raw `toLocaleDateString` sites in 26 files plus `formatDate` (imported by 19 files) share the bug; 5 billing pages independently patched it with `new Date(s + 'T00:00:00')` (InvoicesPage:34, ReceiptsPage:13, CashApplicationPage:11, CashDistributionPage:20, DisbursementsPage:20) — so the same policy date renders differently on PoliciesPage vs InvoicesPage. Combined with X1, an evening-bound policy displays a date two days off round-trip. — Fix: fix `formatDate`/add `formatDateOnly` in lib/utils, sweep the 47 call sites + 9 local `fmtDate` clones (M).

**X3 [P1] — Failed queries are indistinguishable from empty data** — pattern `const { data: x = [] } = useQuery(...)` in ReceiptsPage, InvoicesPage, SubmissionsPage; `PolicyDetailPage.tsx:280`/`SubmissionDetailPage.tsx:907` ("not found." for any error incl. 500) — 115 `data = []` destructure-defaults across 40 files vs only 13 `isError` usages in 7 files; a dead API shows "No invoices found"/EmptyState. On accounting pages this reads as "nothing pending" — hidden data. — Fix: shared `<QueryBoundary>`/error row + sweep the 40 files (M).

**X4 [P1] — Five competing error-message extraction patterns; six pages carry private copies of the same helper** — helper duplicated 6x with 3 divergent variants: `AdminBordereauxProfilesPage.tsx:20`, `LegalRequirementsPage.tsx:1133` (misses `detail`), `PolicyFormsAdminPage.tsx:191`, `ProgramConfigurationAdminPage.tsx:690`, `SurplusLinesAdminPage.tsx:670`, `UnderwritingControlsAdminPage.tsx:1126`; plus `SubmissionDetailPage.tsx:51` `getSaveErrorMessage` (the only one surfacing the ASP.NET validation `errors` dict). '...'` = 97 occurrences/30 files; raw `toast.error(e.message)` = 15 occurrences/8 pages; static generic strings ≈ 50 (e.g. FeesAdminPage 'Save failed' hides P0001 Program-SOT reasons). — Fix: `lib/apiError.ts#getApiErrorMessage` (BordereauxProfiles variant + errors dict), delete 7 locals, sweep 286 `toast.error` sites (M).

**X5 [P1] — Mutations with no `onError` at all fail silently** — `SubmissionDetailPage.tsx` (26 useMutation, 19 onError — 7 silent), `QuoteDetailPage.tsx` (17 vs 16), `PolicyDetailPage.tsx` (19 vs 18) — app-wide ≈228 mutations vs 217 onError; ~11 mutations toast nothing on failure. — Fix: register a `MutationCache` global onError fallback toast in `lib/queryClient.ts` (S).

**X6 [P1] — Bind flow never invalidates policies/submissions: bound policy invisible in lists for up to 5 minutes** — `QuoteDetailPage.tsx:626-638` — `bindMutation.onSuccess` invalidates only `['quotes', quoteId]` and `['quotes','by-submission']`, then navigates to `/policies/:id`; `['policies']`, `['submissions']`, dashboard keys untouched.
