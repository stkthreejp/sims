# Lane A — Admin & Configuration findings

**A1 [P0] — Program Configuration: switching programs keeps stale child-edit state → wrong-target saves** — `frontend/src/pages/admin/ProgramConfigurationAdminPage.tsx:340,132-181` — Clicking another program in the list (line 340) only sets `selectedProgramId`; `editingCarrierId`, `lobParentCarrierId`, `stateParent`, and all child forms survive the switch, so "Save" calls e.g. `updateCarrier(programB.id, carrierIdFromProgramA)` (line 137). The LOB/state selects render blank for stale IDs but the state value persists, keeping Save enabled — a cross-program write with no visual warning. — Fix: reset all child edit state (forms + editing IDs + parents) in a `useEffect` on `selectedProgram?.id` change (S).

**A2 [P0] — "Applies to Flat Cancellations" label means the opposite of what it does** — `frontend/src/pages/admin/FeesAdminPage.tsx:484`; backend `FeeCalculationService.cs:59` — The engine filters `!(v.AppliesToFlatCancellations && !ctx.IsFlatCancellation)`, i.e. checking the box restricts the fee to ONLY flat cancellations; the label (in the "Auto Apply" inclusion group) reads as additive. An admin checking it silently stops the fee on every normal transaction. — Fix: relabel "Only applies to flat cancellations" and move it next to the other "Only…" restrictions (S).

**A3 [P0] — Taxability modal can silently wipe state-taxability config** — `frontend/src/pages/admin/FeesAdminPage.tsx:675,173-177` — "Taxable States" seeds the editor from `versions[0]?.nonTaxableStates ?? []`; if the versions query is still loading, the fee has no versions, or `versions[0]` isn't the current version, the modal opens with all 51 states checked and Save (`setStateTaxability`) overwrites the definition with an empty non-taxable list — no diff, no confirm. — Fix: fetch taxability from the definition endpoint (or block open while `loadingVersions`), and show a changed-states summary before save (M).

**A4 [P0] — Policy number sequence/assignment delete has zero confirmation** — `frontend/src/pages/admin/PolicyNumbersAdminPage.tsx:400,458` — The trash icons call `deleteSequence.mutate(...)` / `deleteAssignment.mutate(...)` directly. One misclick deletes the policy-number identity generator or the assignment that routes numbering for a carrier/LOB/state; every other admin page wraps delete in `confirm()`. — Fix: add confirm dialogs including usage info (assignments referencing the sequence) (S).

**A5 [P0] — NextNumber is freely editable with no duplicate-number warning** — `frontend/src/pages/admin/PolicyNumbersAdminPage.tsx:285` — Editing a live sequence exposes `nextNumber` as a plain number input; lowering it will mint duplicate policy numbers with no warning, preview shows the new numbers as if normal. — Fix: warn (and require confirm) when saving a `nextNumber` lower than the stored value on an existing sequence (S).

**A6 [P1] — PercentOfNet checkbox is offered but backend fail-closes, and the page swallows the error** — `frontend/src/pages/admin/FeesAdminPage.tsx:371-374,164`; backend `FeeAdminService.cs:318-319` — Backend now rejects `PercentOfNet=true` with `PERCENT_OF_NET_UNSUPPORTED`, but the checkbox still renders as a normal option and `saveVersion.onError` is a hardcoded `toast.error('Save failed')`, so the admin gets no reason. — Fix: remove/disable the checkbox with an explanatory note, and surface `errorMessage` in the toast (S).

**A7 [P1] — Program-spine caches under 4 query keys; `['program-configurations','options',*]` is never invalidated** — `frontend/src/pages/admin/ProgramConfigurationAdminPage.tsx:103`, `PolicyNumbersAdminPage.tsx:88`, `PolicyFormsAdminPage.tsx:235`, `frontend/src/lib/queryClient.ts:6` — Program Config saves invalidate only `['admin','program-configurations']`; Policy Numbers/Policy Forms (and SubmissionDetail) read `['program-configurations','options',…]`, which with `staleTime: 5min` + `refetchOnWindowFocus:false` shows the pre-save spine for up to 5 minutes ("my new state doesn't exist" symptom mid-setup). — Fix: standardize on one key family (or invalidate both prefixes in `refreshPrograms`) (S).

**A8 [P1] — Fee version "Effective Date *" is not enforced; blank date saves fail generically** — `frontend/src/pages/admin/FeesAdminPage.tsx:335,346-348` — Save Version is disabled only for `missingVendorPayee || incompleteProgramScope`; a new version with empty `effectiveDate` submits and returns the opaque "Save failed" toast. Same page: `createDef`, `disableVersion`, `saveTaxability` all discard server error messages (lines 152, 170, 176). — Fix: add `!form.effectiveDate` to the disabled condition and use a shared `getApiErrorMessage` in all four onError handlers (S).

**A9 [P1] — Factor table edit/paste can persist NaN factors and unvalidated dimensions** — `frontend/src/pages/admin/AdminRatingPlanVersionPage.tsx:54,70,90-96` — Clearing a factor cell then saving sends `parseFloat('') = NaN` (serialized as `null`) for that row; paste-import builds dimension keys from whatever headers were pasted with no check against `table.dimensionNames`, so a wrong header silently replaces all rows with mismatched dims the rater will never match (rates as 0/default). — Fix: block save on non-numeric factors and reject paste when headers ≠ `dimensionNames` (M).

**A10 [P1] — Bordereaux state code is stored lowercase; uppercase is CSS-only** — `frontend/src/pages/admin/AdminBordereauxProfilesPage.tsx:161` — `set('stateCode', e.target.value)` with `style={{ textTransform: 'uppercase' }}` — the visual transform doesn't change the value, so "tx" is persisted and any case-sensitive scope match on export silently drops rows. Also free text: accepts "ZZ". — Fix: `.toUpperCase()` in the setter and validate against a shared state list (S).

**A11 [P1] — Bordereaux profile identity (name/program/carrier/LOB/state/date basis) cannot be edited after create** — `frontend/src/pages/admin/AdminBordereauxProfilesPage.tsx:323-380` — `ProfileForm` renders only in create mode; the detail view offers only Activate/Deactivate plus the setup panel (tabs/columns/mappings). **A12 [P1] — AI Settings: the only consumed use case is locked, the four dead ones are editable** — `frontend/src/pages/admin/AiSettingsAdminPage.tsx:145,162` — `disabled={setting.useCase === 'DocumentExtraction'}` freezes the one setting the backend actually reads, while RiskScoring/ReferralJudgment/NarrativeDrafting/BatchTriage present a full model+prompt+audit workflow that drives nothing. **A13 [P1] — Workflows admin is dead-on-arrival: empty Trigger Event list permanently disables Create with no hint** — `frontend/src/pages/admin/WorkflowsAdminPage.tsx:57-60,68`; backend has no `SystemEvent` seed (`SystemEventConfiguration.cs` has no `HasData`) — With zero system events the required dropdown shows only "Select event…", Create stays disabled forever, and the page gives no explanation; onError is also a generic 'Create failed'. — Fix: seed the SystemEvents catalog (backend) and render an explicit "No trigger events available" empty state (M).

**A14 [P1] — Intermediary brokerage rate accepts whole-number percent (7.5 saves as 750%)** — `frontend/src/pages/admin/IntermediariesAdminPage.tsx:566-577,166` — `min=0 max=1` HTML attributes don't block typed values and `toSetupPayload` sends `Number(form.brokerageRate)` unchecked; `saveSetup()` validates everything except the rate.
