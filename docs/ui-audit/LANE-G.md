# Lane G — Design-Guide Adherence findings

**Overall verdict:** The guide is genuinely adopted, not aspirational — `index.css` mirrors `tokens.css` faithfully (every token present, values exact, plus a sanctioned shadcn HSL mapping), and `sd-*`/`subs-*` classes are used across ~58 files. But enforcement stops at the shared-class layer: 3,019 inline `style={{}}` objects across 70 files re-implement guide components per page, a cluster of admin/rating/compliance pages is written in an entirely foreign Tailwind palette, and status pills alone have 8 competing implementations. The codebase diverges from itself more than `index.css` diverges from canon — the highest-leverage work is consolidation, not re-theming.

**G1 [P1] — StatusBadge fractured into 8 implementations with 3+ visual languages** — `components/common/StatusBadge.tsx:6` (canonical, `sd-pill` + dot) vs local clones at `billing/PeriodClosePage.tsx:24`, `billing/SyncHealthPage.tsx:23`, `reports/ReportsPage.tsx:1236`, `admin/AdminRatingPage.tsx:19`, `admin/AdminRatingPlanDetailPage.tsx:11`, `admin/AdminRatingPlanVersionPage.tsx:18`, `quotes/QuoteWriteupPage.tsx:856` — Locals render square-corner Tailwind badges with no dot (guide §11: dot prefix "mandatory", radius `--r-pill`); AdminRatingPage uses `bg-emerald-100/bg-amber-100` — outside the palette entirely. — Fix: delete locals, extend shared StatusBadge with a semantic-variant prop (M).

**G2 [P1] — Admin/compliance cluster built in Tailwind palette, including a second blue** — 621 `slate/blue/emerald/amber/red-NNN` class occurrences across 38 files; worst: `PolicyFormsAdminPage.tsx` (67), `AdminRatingPlanDetailPage.tsx` (43), `ProgramConfigurationAdminPage.tsx` (36), `IntermediariesAdminPage.tsx` (35), `SurplusLinesAdminPage.tsx` (33), `InsuredCreatePage.tsx`/`InsuredEditPage.tsx` (33/34) — `bg-blue-600` primary buttons (46 `*-blue-*` occurrences, 20 files) render #2563eb, a direct hit on the guide's "No second blue"; these pages use zero `sd-btn`. — Fix: sweep cluster to `sd-btn`/`sd-input`/token classes; lint rule forbidding Tailwind color utilities (L).

**G3 [P1] — Phantom tokens whose hardcoded fallbacks always render off-palette hexes** — `reports/ReportsPage.tsx:77-80,1216-1248`, `admin/AdminBordereauxProfilesPage.tsx:71-72`, `reports/BordereauxWorkbenchPage.tsx:177` — `var(--green-soft, #f0fdf4)`, `var(--yellow-soft, ...)`, `var(--red-soft, ...)`, `var(--good-soft, ...)`, `var(--warn-soft, ...)` reference tokens that exist nowhere, so the Tailwind fallbacks ship 100% of the time — the exact "new tokens silently introduced in code" anti-pattern the guide forbids. — Fix: replace with `--good-bg`/`--warn-bg`/`--bad-bg`, or add soft variants to tokens.css first (S).

**G4 [P1] — Two page-gutter regimes, both off-spec (double padding on 20 pages)** — `components/layout/AppLayout.tsx:16` pads `<main>` with `--container-pad` (28px all sides), yet 20 pages (SubmissionsPage:174, PoliciesPage:170, InsuredsPage:50, all billing pages, AgentsPage, CarriersPage, InboxPage, TaskQueuePage…) also wrap in `.subs-wrap` (`index.css:809`, `20px 28px 60px`) → 56px side gutters there vs flat 28px elsewhere; guide spec is page wrap `20px 28px 60px`, once. — Fix: zero AppLayout main padding and make `.subs-wrap` the single page wrapper (S code, M verification).

**G5 [P1] — 3,019 inline style objects rebuild guide components per page** — counts: `ReportsPage.tsx` (299), `AgentDetailPage.tsx` (223), `PolicyDetailPage.tsx` (195), `SubmissionDetailPage.tsx` (185), `CarrierDetailPage.tsx` (176), `QuoteDetailPage.tsx` (146), `AdminRatingPlanVersionPage.tsx` (121) — most reference tokens for color but hardcode 333+ numeric `fontSize` values bypassing the `--fs-*` scale; each detail page re-derives cards, field grids, toolbars that `sd-card`/`sd-field` already define. — Fix: extract repeated patterns into the class system page-by-page, starting with the four detail pages (L).

**G6 [P1] — Page H1 anarchy: 16–24px, weights up to 750** — guide §23: H1 is 22–24px/600. Found: 16px/700 `AdminBordereauxProfilesPage.tsx:275`; 18px `QuoteWriteupPage.tsx:268`; 20px/700 `AdminShadowRatingPage.tsx:113`; 20px/750 `BordereauxWorkbenchPage.tsx:401`; `text-xl` on AdminRatingPage:166, AdminRatingPlanDetailPage:193, PolicyFormsAdminPage:599; 22px `subs-h1`; 24px PageHeader. A compliant shared `PageHeader` exists and is used by only 37 of ~60 pages. — Fix: mandate PageHeader (or `subs-h1`) everywhere (M).

**G7 [P2] — Shared StatusBadge silently renders an invisible pill for unknown statuses** — `StatusBadge.tsx:8` emits `sd-pill ${status.toLowerCase()}`; `index.css:483-500` defines only 17 status classes, so any other value (e.g. `InvoicesPage.tsx:152` passes untyped `inv.status`) yields a transparent, colorless pill. — Fix: add a `.sd-pill` default bg/color and a dev-mode warning for unmapped statuses (S).

**G8 [P2] — Sky-blue sub-palette inside Quote Detail** — `QuoteDetailPage.tsx:107-108` (`#f0f9ff`, `#075985` active stepper) and `:177` (`#7dd3fc` border) — Tailwind sky shades next to the brand blue on the same screen; guide: one accent family only. — Fix: swap to `--accent-soft`/`--accent-ink`/`--accent-light` (S).

**G9 [P2] — Hand-mixed semantic colors that drift from the warn/bad tokens** — `TaskQueuePage.tsx:23` Blocked pill `#fff0d6/#8a5a00/#e4b85d` (near-dupes of `--warn-bg #fdf3df`/`--warn-fg #8a5a0b`); `#8a5a00` repeated in `ReportsPage.tsx:1217,1228,1238`; `BordereauxWorkbenchPage.tsx:123-165` uses `#f59e0b/#92400e/#991b1b/#7f1d1d/#fca5a5/#fde68a`; `QuoteAutoSafetyPanel.tsx:708,729` risk dial `#dc2626/#d97706/#059669/#94a3b8/#e2e8f0`; `UnderwritingControlEnforcementPanel.tsx:92` `#f0fdf4/#bbf7d0/#166534`. Two subtly different "warning ambers" coexist. — Fix: global replace with `--warn-*`/`--bad-*`/`--good-*` pairs (M).

**G10 [P2] — Unsanctioned gradient on dashboard funnel bars** — `DashboardPage.tsx:113` `linear-gradient(90deg, var(--accent-light), var(--accent))` — guide "Avoid this": no gradients except the hero-KPI wash (line 315 uses that one legitimately). — Fix: flat `--accent` fill (S).

**G11 [P2] — Broken focus indicator via undefined `--focus` token** — `index.css:601` `.sd-quote:focus-visible { outline: 2px solid var(--focus); }` — no `--focus` exists (only `--focus-ring`, a shadow), so keyboard focus on quote rows loses its ring. — Fix: `box-shadow: var(--focus-ring)` or `outline-color: var(--accent)` (S).

**G12 [P2] — Topbar diverges from guide §09: no breadcrumb, dead bell** — `Topbar.tsx:52-103` — guide specifies left breadcrumb with search/bell/avatar right; code puts search left, no breadcrumb, and the notifications bell (line 98) has no handler. — Fix: add breadcrumb slot fed by route metadata; move search right; wire or remove the bell (M).

**G13 [P2] — Error states missing on ~90% of pages despite guide checklist** — Only 6 files check `isError` (AgentDetailPage, CarrierDetailPage, QuoteDetailPage, ClaimsPage, QuoteWriteupPage, InboxDetailPage); `SubmissionsPage.tsx` — the flagship list — has zero error handling, so a failed fetch reads as an empty book. — Fix: shared QueryStateGuard/ErrorState component wired into list pages (M).

**G14 [P2] — Two blessed form-control systems with different radii and focus treatments** — `index.css:233-262` (`.sims-input`, radius 8px, focus ring shadow; `.sims-field-label` 10.5px uppercase) vs `index.css:383-440` (`.sd-input`, radius 7px, border-only focus; `.sd-label` 12px sentence case) — same concept, two specs; pages mix freely. — Fix: pick one (sd-*), alias the other, migrate (M).

**G15 [P2] — Empty-state concept implemented three ways** — shared `EmptyState.tsx` (22 files) vs `.admin-empty` CSS class (`index.css:293`; EscalationRules, HolidayCalendar, TaskTypes, UnderwritingControls admin pages) vs ad-hoc "No results…" strings in 10 more files (ReportsPage x5, PoliciesPage x2, etc.). — Fix: converge on EmptyState (M).

**G16 [P3] — Token values hardcoded as literals where the token exists** — `ErrorBoundary.tsx:28-29` (`#f3c6be`/`#b33a2a` = `--danger-border`/`--error-border`), `QuoteAutoSafetyPanel.tsx:110` (same pair), `index.css:680` (`border-color: #cfe0ef` though `--accent-border` exists). — Fix: replace literals with `var()` references (S).

**G17 [P3] — Sidebar drift from guide §08: no sub-menus, off-spec section label, no responsive collapse** — `Sidebar.tsx:19-25` SectionLabel 9.5px/700 vs guide 10px; guide's sub-menu pattern unimplemented — 27 flat items including 19 under "Admin"; guide requires sidebar collapse at <980px but index.css has only 1100/1200px media queries. — Fix: adopt sub-menu grouping for Accounting/Admin; add collapse breakpoint (M).

**G18 [P3] — Button size/variant set diverges from guide §10** — `.btn-mini` (24px, guide's third size) missing from index.css; code invents `sd-btn.accent` (index.css:536) and `sd-btn.success` (:540) beyond the guide's four variants. — Fix: add btn-mini; document accent/success in the guide or fold into outline/primary (S).

**G19 [P3] — Date and null formatting off the §21 contract** — bare `toLocaleDateString()` renders `M/D/YYYY` vs guide "Mmm DD, YYYY": `PolicyDetailPage.tsx:796`, `AdminJobsPage.tsx:217`, `LegalRequirementsPage.tsx:1126`, `QuoteAutoSafetyPanel.tsx:1007`; nulls render `'-'` instead of em-dash; a compliant `lib/utils.ts:12 formatDate` exists but ~10 pages define private clones. — Fix: standardize on lib/utils formatters, delete locals (S).

**G20 [P3] — index.css self-inconsistencies** — `.sd-pill.cancelled` declared twice with different token pairs (`index.css:490` uses `--pill-declined-*`, `:498` uses `--bad-*` — same hex today, will fork silently); `.sd-card-head` bottom border is `--line-2` (:361) where guide §14 specifies `var(--line)`. — Fix: delete duplicate rule; align header border (S).

**Worst offenders:** inline-style volume — ReportsPage (299), AgentDetailPage (223), PolicyDetailPage (195), SubmissionDetailPage (185), CarrierDetailPage (176), QuoteDetailPage (146); foreign palette — PolicyFormsAdminPage (67 Tailwind color classes + 8 hex), AdminRatingPlanDetailPage (43), ProgramConfigurationAdminPage (36), IntermediariesAdminPage (35); raw hex — BordereauxWorkbenchPage (14), QuoteAutoSafetyPanel (13), ReportsPage (12).
